# 0002. Свой тонкий клиент MAX API вместо библиотеки

Статус: принято, 2026-10-16

## Контекст

Официального Python SDK нет (последний коммит 2025-07). Живая сторонняя библиотека `maxapi` неофициальная и отстаёт от изменений API, например в ней всё ещё есть удалённый `GET /chats`. Боту нужно около десятка эндпоинтов.

## Решение

Свой клиент `gatebot/maxbot/client.py` на aiohttp:
- хост `platform-api2.max.ru`;
- заголовок `Authorization`;
- CA Минцифры подключается точечно через `SSLContext`;
- ограничение частоты запросов (≤25 rps);
- ретраи на 429, 5xx и сетевые ошибки;
- проверка `success` в ответах `SimpleQueryResult`.

Диалоги построены на callback-payload (`pay`, `tariff:3`, `adm:...`) без FSM-фреймворка. Состояние админки хранится в памяти, после рестарта админ просто заново открывает `/admin`.

Ядро (подписки, платежи, воркер) зависит только от порта `core.ports.Messenger`, а не от MAX.

## Последствия

- Изменения API отслеживаем сами по changelog dev.max.ru.
- Сертификат `gatebot/certs/russian_trusted_root_ca.pem` действует до 2032-02-27.
