# 0004. Один вебхук Prodamus на два бота: маршрутизатор

Статус: принято, 2026-10-16

## Контекст

В кабинете Prodamus указан URL вебхука TG-бота: `https://apps.r3lax3.site/paygatebot/prodamus/webhook`. Владелец не хочет ничего менять ни в кабинете, ни в TG-боте. При этом уведомления об оплатах MAX-бота должны доходить до MAX-бота.

## Решение

- `POST /prodamus/router` в MAX-боте принимает уведомления из кабинета:
  - **наше** уведомление обрабатывает сам. Нашим считается `customer_extra` вида `max:<id>` или `order_num`, найденный в нашей базе;
  - **чужое** пересылает в `prodamus_forward_url` (вебхук TG-бота) без изменений: то же тело, `Content-Type` и `Sign`. Ответ TG-бота возвращается Prodamus, а при недоступности TG-бота отдаётся 502, и Prodamus повторит уведомление.
- nginx направляет в маршрутизатор только точный путь, который указан в кабинете. Если MAX-бот недоступен, nginx отправляет запрос напрямую TG-боту (`error_page 502 503 504`), поэтому оплаты TG не зависят от MAX-бота:

```nginx
location = /paygatebot/prodamus/webhook {
    proxy_pass http://127.0.0.1:8081/prodamus/router;
    proxy_intercept_errors on;
    error_page 502 503 504 = @tg_prodamus;
}
location @tg_prodamus {
    proxy_pass http://127.0.0.1:8003/prodamus/webhook;
}
```

- Страница после оплаты задаётся в каждой ссылке параметром `paid_content` (`bot_link`). Ссылки MAX-бота ведут в MAX, ссылки TG-бота — в Telegram.

## Последствия

- Пока MAX-бот работает, оплаты TG проходят через него. Сбой MAX-бота закрывается nginx-фолбэком.
- Если в кабинете поменяют URL, маршрутизацию придётся перенастроить.
