# 0001. Закрываем групповой чат, вход контролируем удалением

Статус: принято, 2026-10-16

## Контекст

В Telegram-версии вход в канал шёл через заявку (`chat_join_request`): бот одобрял её только при активной подписке. В MAX Bot API (см. `docs/research/max-bot-api.md`):

- нет заявок на вступление и нет персональных или одноразовых инвайт-ссылок, есть только общая ссылка чата;
- добавить человека в чат через API нельзя (`POST /chats/{id}/members` ограничен с 09.09.2026);
- удалять участников бот может **только в групповых чатах**: право `add_remove_members` для ботов в каналах недоступно.

## Решение

- Закрытым делаем **групповой чат** (`gated_chat_ids`). Канал закрыть ботом нельзя.
- Оплатившему бот отдаёт общую ссылку группы (`invite_links` или `Chat.link`).
- На событие `user_added` в закрытом чате бот проверяет подписку. Если её нет, удаляет участника с `block=false` и пишет ему в личку. Исключения: владельцы, люди, добавленные владельцем, и боты.
- При окончании подписки бот удаляет участника с `block=false`. Метода разблокировки в API нет, а после повторной оплаты человек должен суметь вернуться по ссылке.
- Страховка от пропущенных событий: опциональная сверка участников с базой в воркере (`reconcile_members`).

## Последствия

- Посторонний, получивший ссылку, на несколько секунд оказывается в группе и может увидеть последние сообщения. Средствами API это окно не закрыть.
- Если ссылка утекла, её меняют в клиенте MAX и обновляют `invite_links`.
- Бот должен быть администратором группы с правами `read_all_messages` (без него события не приходят) и `add_remove_members`.
