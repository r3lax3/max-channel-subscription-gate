# 0003. Prodamus: общий аккаунт с TG-ботом, поиск платежа, подпись

Статус: принято, 2026-10-16. Обновлено после ревью.

## Контекст

- TG-бот и MAX-бот могут работать на одном аккаунте Prodamus.
- В уведомлении об оплате Prodamus присылает **наш** номер заказа в `order_num`, а в `order_id` — свой внутренний номер ([пример уведомления](https://help.prodamus.ru/payform/uvedomleniya/kak-ustroena-otpravka-uvedomlenii-ob-oplate)). TG-версия искала по `order_id` и фактически всегда шла запасным путём: «последний неоплаченный платёж пользователя», без сверки суммы.
- Параметр ссылки `urlNotification` Prodamus учитывает не во всех интеграциях: по документации он требует `sys`, а в официальном примере помечен «пока только для Advantshop».

## Решение

- Уведомления доставляются на URL, добавленные в кабинете Prodamus («Настройки → URL для уведомлений», можно несколько). В кабинет добавляется URL этого бота. `urlNotification` передаём дополнительно, на случай если сработает.
- Оба бота получают уведомления друг друга и отсеивают чужие:
  - `customer_extra` у нас `max:<id>`; TG-бот такое не распознаёт как свой telegram_id;
  - мы игнорируем уведомления без префикса `max:`.
- Поиск платежа идёт в таком порядке:
  1. `order_num`;
  2. `order_id`;
  3. запасной путь: пользователь из `customer_extra` и неоплаченный (pending или протухший) платёж **с той же суммой**.
- Перевод в `success` атомарный (`UPDATE ... WHERE status != 'success'`) и коммитится вместе с продлением подписки. Повтор уведомления подписку повторно не продлевает.
- Если пришла наша оплата, которую не удалось сопоставить, бот пишет владельцам: деньги пришли, доступ нужно выдать вручную.
- При внутренней ошибке отвечаем 500, ничего не закоммичено, и Prodamus повторит уведомление.
- Вебхук проверяет подпись (заголовок `Sign`) по алгоритму официальных Hmac.php и Hmac.js. Без неё «оплатить» подписку мог бы кто угодно, кто знает URL.
